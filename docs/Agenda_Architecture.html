00 / Orientation

How to read this

Agenda runs as three cooperating OS processes: a Rust program, a web view that the Rust program hosts, and a Python program that the Rust program launches. Most of the confusion in this kind of stack comes from not knowing which process a given line of code runs in, so every diagram here draws process boundaries explicitly.

Tauri IPC (in-app, Rust ⇄ WebView) HTTP on 127.0.0.1 stdin / stdout pipe local disk / OS vault internet / outside the bundle rejection / failure

Solid outlined panels are OS processes. Dashed outlines are trust boundaries or things the app doesn't own.

01 / Component map

Every component, process, and channel

Why there are two different pipes out of the WebView

Tauri IPC

For: things only the native shell can do, like getting the backend port and secret, showing an OS notification, opening a URL in the system browser, and hearing about sidecar restarts.

It's in-process message passing that Tauri serializes as JSON. It isn't a network socket, so nothing outside the app can reach it.

Loopback HTTP

For: all domain reads and writes (spaces, events, tasks, sync, AI). Python owns the rules, so the WebView talks to Python directly and Rust stays out of the request path.

It's a real TCP socket on 127.0.0.1, so any local process could try to connect. That's why the bearer secret, the Host check, and CORS exist.

Why not route API calls through Rust? You could proxy every call as WebView → invoke() → Rust → HTTP → Python, which would avoid CORS entirely. The spec deliberately doesn't. Every endpoint would need a Rust shim, and you'd lose the generated typed client and the browser's standard fetch tooling. Keeping Rust thin means the frontend–backend contract is just OpenAPI.

02 / Tauri primer

Tauri for someone who hasn't used it

Mental model: a Tauri app is a Rust program that opens a window containing the operating system's own browser engine and loads your built React files into it. On Windows that engine is WebView2 (Edge/Chromium), on macOS it's WKWebView (Safari), and on Linux it's WebKitGTK. Unlike Electron, no browser ships inside the app, which keeps installers small, but you're testing against three engines instead of one.

The Rust half has full OS access. The web half is a sandboxed page with no OS powers at all except those the Rust half explicitly exposes. Tauri gives you four ways to expose them:

1 · Commands: the WebView calls Rust

A Rust function annotated with #[tauri::command] becomes callable from JavaScript through invoke(). Arguments and return values are serialized as JSON using serde. In Agenda the frontend needs this for exactly one thing, learning where the backend is and which secret to send:

// apps/desktop/src-tauri/src/commands.rs
#[derive(serde::Serialize)]
pub struct BackendConfig { base_url: String, token: String }

#[tauri::command]
pub fn get_backend_config(state: tauri::State<'_, BackendState>) -> Result<BackendConfig, String> {
    let guard = state.0.lock().unwrap();
    let b = guard.as_ref().ok_or_else(|| "backend not ready".to_string())?;
    Ok(BackendConfig { base_url: format!("http://127.0.0.1:{}", b.port), token: b.token.clone() })
}
// apps/desktop/src/api/backend.ts
import { invoke } from "@tauri-apps/api/core";
const cfg = await invoke<{ base_url: string; token: string }>("get_backend_config");

A Result::Err in Rust becomes a rejected Promise in TypeScript. Commands are registered once with .invoke_handler(tauri::generate_handler![get_backend_config]).

2 · Events: Rust pushes to the WebView

A command is request/response and initiated by the page. An event is fire-and-forget and can come from Rust at any time. Agenda uses events for sidecar lifecycle changes, so the UI can show "reconnecting…" and drop a stale port and token.

// Rust
use tauri::Emitter;
app.emit("backend:ready", ())?;

// TypeScript
import { listen } from "@tauri-apps/api/event";
await listen("backend:ready", () => resetApiClient());

3 · Shared state: app.manage()

Rust code that commands need (the current port and secret) lives in a value registered once with .manage(...). Any command can then ask for it as a tauri::State<T> parameter. It's shared across threads, so wrap mutable parts in a Mutex.

#[derive(Default)]
pub struct BackendState(pub std::sync::Mutex<Option<Backend>>);
pub struct Backend { pub port: u16, pub token: String }

4 · Plugins + capabilities: opt-in OS powers

Notifications, opening URLs, spawning processes and so on come from official plugins (tauri-plugin-notification, -opener, -shell, -single-instance). Each plugin has a Rust half that you register and an npm half that you import. In Tauri v2 a page can call a plugin only if a capability file grants that permission to that window. This is Tauri's least-privilege boundary.

// apps/desktop/src-tauri/capabilities/default.json
{
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "notification:default",
    "opener:default"
  ]
}
There's deliberately no shell:* permission for the page. The Rust side spawns the Python sidecar, and the WebView can never launch processes, even if an XSS bug in the UI let an attacker run JavaScript.

The sidecar mechanism

A "sidecar" is Tauri's term for an extra executable that ships inside your app bundle. You list it in tauri.conf.json under bundle.externalBin and build one file per platform with the Rust target triple appended to the name. Tauri picks the right one at bundle time.

// apps/desktop/src-tauri/tauri.conf.json (excerpt)
{
  "bundle": { "externalBin": ["binaries/agenda-backend"] },
  "app": {
    "windows": [{ "label": "main", "title": "Agenda" }],
    "security": {
      "csp": "default-src 'self'; connect-src ipc: http://ipc.localhost http://127.0.0.1:*"
    }
  }
}

# files PyInstaller/Nuitka must produce (get yours with: rustc --print host-tuple)
src-tauri/binaries/agenda-backend-x86_64-pc-windows-msvc.exe
src-tauri/binaries/agenda-backend-aarch64-apple-darwin
src-tauri/binaries/agenda-backend-x86_64-unknown-linux-gnu

The CSP line matters. connect-src lists the only places page JavaScript may fetch: Tauri's own IPC endpoints plus http://127.0.0.1 on any port, because the port is random per launch. Every other origin is blocked by the engine before a request leaves the page.

03 / Startup handshake

How Rust, Python, and the WebView find each other

On every launch the backend gets a random port and a fresh secret. Nothing is written to disk, so the three processes need a handshake to agree on both. The spec describes the steps (§04). This section pins down the exact bytes.

Rust side

// src-tauri/src/sidecar.rs (core of it)
use tauri_plugin_shell::{process::CommandEvent, ShellExt};

let token = random_hex_32_bytes();        // 256-bit, RAM only
let data_dir = app.path().app_data_dir()?;
let (mut rx, mut child) = app.shell()
    .sidecar("agenda-backend")?
    .args(["--data-dir", data_dir.to_str().unwrap()])
    .spawn()?;

// secret over stdin: argv and env are readable
// by other local processes; a pipe is not
child.write(format!("{token}\n").as_bytes())?;

let port = loop {
    match rx.recv().await {
        Some(CommandEvent::Stdout(line)) => {
            let line = String::from_utf8_lossy(&line);
            if let Some(p) = line.trim()
                .strip_prefix("AGENDA_READY port=") {
                break p.parse::<u16>()?;
            }
        }
        Some(CommandEvent::Stderr(l)) => log_line(&l),
        Some(CommandEvent::Terminated(t)) =>
            anyhow::bail!("exited early: {:?}", t.code),
        _ => {}
    }
};
wait_for_ready(port, Duration::from_secs(30)).await?;
*app.state::<BackendState>().0.lock().unwrap() =
    Some(Backend { port, token });
app.emit("backend:ready", ())?;
// keep reading rx in a task: Terminated → restart (§08)

Python side

# services/backend/app/main.py
import socket, sys, threading, uvicorn
from app.api import create_app

def main() -> None:
    # 1. first line on stdin is the launch secret
    token = sys.stdin.readline().strip()

    # 2. loopback only; port 0 = "OS, pick a free one"
    sock = socket.socket()
    sock.bind(("127.0.0.1", 0))
    port = sock.getsockname()[1]

    app = create_app(token=token, port=port)

    # 3. the one line Rust is waiting for.
    #    flush=True: piped stdout is block-buffered
    print(f"AGENDA_READY port={port}", flush=True)

    server = uvicorn.Server(
        uvicorn.Config(app, log_config=None))

    # 4. stdin EOF = parent died → shut down,
    #    so a crashed Rust never leaves an orphan
    def watch_parent():
        sys.stdin.read()
        server.should_exit = True
    threading.Thread(target=watch_parent,
                     daemon=True).start()

    server.run(sockets=[sock])

Binding the socket yourself, rather than letting uvicorn do it, means the port is known before the server starts. /health/ready returns 503 until the database is open and migrated, and Rust polls it.

Rule for the stdout pipe: once stdout is a protocol channel, nothing else may print to it. Configure all Python logging to go to stderr and a file, and give protocol lines a fixed prefix (AGENDA_READY, AGENDA_EVENT) so Rust can ignore anything unexpected instead of misparsing it.
04 / TypeScript → Python

One request, hop by hop

This traces POST /api/v1/spaces/{space_id}/tasks, the example from spec §08, from a button click to a SQLite row and back. Each hop is a place where the request can be stopped, and the figure shows the status you get when it is.

①②

Component and typed call

The component calls a typed client method. The path string, path params, headers, and body are all checked by tsc against the generated paths type. A typo in a field name is a compile error, not a 422 at runtime.

const { data, error } = await (await api()).POST("/api/v1/spaces/{space_id}/tasks", {
  params: { path: { space_id: spaceId }, header: { "Idempotency-Key": crypto.randomUUID() } },
  body: { title: "Take out recycling", due_date: "2026-10-20", rrule: "FREQ=WEEKLY;BYDAY=TU" },
});
if (error) showError(error.error.code);   // error is typed as ErrorEnvelope
③

Client middleware attaches the secret

The client is created lazily from the IPC config and thrown away whenever Rust says the backend restarted, because a restarted sidecar has a new port and a new token.

// apps/desktop/src/api/backend.ts
import createClient from "openapi-fetch";
import type { paths } from "@agenda/contracts";

let client: ReturnType<typeof createClient<paths>> | null = null;

export async function api() {
  if (!client) {
    const cfg = await invoke<BackendConfig>("get_backend_config");
    client = createClient<paths>({ baseUrl: cfg.base_url });
    client.use({ onRequest({ request }) {
      request.headers.set("Authorization", `Bearer ${cfg.token}`);
      return request;
    }});
  }
  return client;
}
listen("backend:restarting", () => { client = null; });
④

WebView fetch(): CSP, then CORS

The page's origin is the Tauri app (tauri://localhost on macOS/Linux, http://tauri.localhost on Windows) and the API is http://127.0.0.1:51873. Those are different origins, so the browser engine applies cross-origin rules:

  • CSP (from tauri.conf.json) is checked first. If 127.0.0.1 isn't in connect-src, the request never leaves the page.
  • Because the request carries an Authorization header and a JSON body, it isn't a "simple" request. The engine first sends an OPTIONS preflight asking "may this origin send these headers?". The real POST goes out only if Python answers yes.

Fails as: a CORS error in the devtools console, with no status visible to your code. This is the most common "it works in curl but not in the app" bug.

⑤⑥

uvicorn, then CORS middleware

uvicorn turns bytes into an ASGI request. CORSMiddleware must be the outermost layer, because the preflight OPTIONS carries no Authorization header and would otherwise be rejected by the bearer check. In Starlette/FastAPI the last middleware added runs first.

⑦⑧

Local boundary: Host header and bearer secret

# services/backend/app/core/security.py
import hmac
from fastapi.middleware.cors import CORSMiddleware

TAURI_ORIGINS = ["tauri://localhost", "http://tauri.localhost"]   # macOS/Linux, Windows
DEV_ORIGINS   = ["http://localhost:1420"]                         # Vite, `tauri dev` only

def install_boundary(app, *, token: str, port: int, dev: bool) -> None:
    expected_host = f"127.0.0.1:{port}"
    expected_auth = f"Bearer {token}".encode()

    @app.middleware("http")
    async def local_boundary(request, call_next):
        if request.headers.get("host") != expected_host:       # ⑦ DNS-rebinding guard
            return error_response(400, "BAD_HOST")
        if not is_public_path(request.url.path):               # /health/*, OAuth callback
            supplied = request.headers.get("authorization", "").encode()
            if not hmac.compare_digest(supplied, expected_auth): # ⑧ constant-time
                return error_response(401, "UNAUTHORIZED")
        return await call_next(request)

    # added last → runs first → answers preflight before the check above
    app.add_middleware(CORSMiddleware,
        allow_origins=TAURI_ORIGINS + (DEV_ORIGINS if dev else []),
        allow_methods=["GET", "POST", "PATCH", "DELETE"],
        allow_headers=["Authorization", "Content-Type", "Idempotency-Key", "If-Match"])

Why the Host check: a malicious web page in the user's normal browser can point its own domain's DNS at 127.0.0.1 ("DNS rebinding"). Its requests then arrive with Host: evil.example, so they're rejected here even before the missing token is noticed.

⑨⑩

Route, app-lock gate, and Pydantic validation

The app-lock gate is a router-level dependency on every domain router, so /auth/unlock stays reachable while the app is locked. FastAPI validates the body against the Pydantic model before your function runs.

class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=200)
    notes: str | None = None
    due_date: date | None = None
    rrule: str | None = None
    assignee_person_id: UUID | None = None

router = APIRouter(prefix="/api/v1", dependencies=[Depends(require_unlocked)])

@router.post("/spaces/{space_id}/tasks", status_code=201,
             response_model=Envelope[TaskOut],
             responses={404: {"model": ErrorEnvelope}, 409: {"model": ErrorEnvelope}})
async def create_task(space_id: UUID, body: TaskCreate,
                      ctx: RequestContext = Depends(request_context),
                      idempotency_key: str | None = Header(default=None)):
    task = await tasks.create(ctx, space_id, body, idempotency_key)
    return Envelope(data=task, request_id=ctx.request_id)
Gotcha: FastAPI only documents error responses you declare in responses=. If you leave them out, the generated TypeScript won't know a 404 returns ErrorEnvelope, and error will be typed as unknown. Register an exception handler that converts RequestValidationError into the spec's error envelope, too.
⑪⑫

Application service and repository

This is where the real rules live: the space is resolved from the URL and checked against the actor, the assignee must belong to the same space, and the row and its outbox event are committed in one SQLite transaction.

async def create(ctx, space_id, body, idem_key) -> Task:
    async with ctx.unit_of_work() as uow:                       # one short write txn
        space = await uow.spaces.get_accessible(space_id, ctx.actor)        # 404 if not
        if body.assignee_person_id:
            await uow.people.require_in_space(body.assignee_person_id, space.id)  # 422
        task = await uow.tasks.add(Task.new(space.id, ctx.actor, body))
        await uow.outbox.add("task.created", aggregate=task)      # same txn
    return task
⑬

Back in TypeScript

openapi-fetch returns { data } for 2xx and { error } otherwise. It never throws on HTTP errors, only on network failure. Treat a network failure as "backend unavailable" and wait for backend:ready, rather than showing an error per widget.

05 / The type contract

One schema, two languages

Python is the source of truth. The TypeScript types are generated from it and are never written by hand, so a rename on one side can't silently break the other.

# services/backend/scripts/export_openapi.py
import json; from app.api import create_app
json.dump(create_app(token="unused", port=0).openapi(),
          open("../../packages/contracts/openapi.json", "w"), indent=2, sort_keys=True)

# packages/contracts/package.json → "generate"
npx openapi-typescript openapi.json -o src/schema.d.ts

# CI step
python scripts/export_openapi.py && npm -w packages/contracts run generate
git diff --exit-code packages/contracts

openapi-typescript produces types only, with zero runtime cost. openapi-fetch is a ~6 kB wrapper around fetch that uses those types. Pydantic field constraints (min_length, formats) appear in the schema but aren't enforced in TS. The server is still the validator.

06 / Backend → frontend

When Python has something to say

HTTP only flows WebView → Python, so Python can't call the UI. The spec covers this with three mechanisms:

Delivering OS notifications: the open decision

The spec says reminders go out "via Tauri", but only Rust can call the notification plugin and only Python knows when a reminder is due. Something has to relay the message:

# Python: one JSON line per event
print("AGENDA_EVENT " + json.dumps({"type": "notify", "id": n.id, "title": n.title, "body": n.body}), flush=True)

// Rust: in the same rx loop that watches for Terminated
if let Some(json) = line.strip_prefix("AGENDA_EVENT ") {
    let ev: SidecarEvent = serde_json::from_str(json)?;
    if let SidecarEvent::Notify { title, body, .. } = ev {
        app.notification().builder().title(title).body(body).show()?;
    }
}

Recommendation: B for OS delivery, with REST for the in-app inbox (read/dismiss). Never put secrets or email content in an event line. Spec §09 already forbids that in payloads.

07 / OAuth across processes

Connecting a Google or Microsoft account

OAuth involves all three processes plus two outsiders. The sidecar does the protocol work, Rust only opens the browser, and the browser hands the result back to the sidecar's loopback port.

  • Why the system browser: Google blocks sign-in inside embedded webviews, and users can see the real URL bar there.
  • Which port: the sidecar's own random API port works. Both Google (desktop client type) and Microsoft accept any port on a loopback redirect URI.
  • Afterwards: the browser tab shows a static "You can close this window" page served by the sidecar, and the UI learns the outcome by polling GET /external-accounts (or by listening on SSE later).
08 / Crashes & restarts

What happens when the sidecar dies

Sidecar crashes

Rust's rx loop receives CommandEvent::Terminated. It clears BackendState, emits backend:restarting (the UI drops its client and shows a banner), backs off, and respawns. Jobs that were mid-flight are reclaimed by lease expiry (spec §09).

Rust crashes

The OS closes the sidecar's stdin pipe. watch_parent() sees EOF and stops uvicorn gracefully, so the DB lock file is released and the next launch starts cleanly.

Second launch

tauri-plugin-single-instance catches it in the new process, focuses the existing window, and exits before any sidecar spawns. The DB lock file is a second line of defense.

Normal quit

On RunEvent::ExitRequested, Rust closes the sidecar's stdin (the same EOF path), waits up to N seconds for exit, then calls child.kill(). Python's shutdown drains workers and checkpoints the WAL.

09 / Dev-mode wiring

What changes under tauri dev

tauri dev starts Vite at http://localhost:1420 with hot reload and points the window at it, so the page origin becomes http://localhost:1420. That's why the CORS allow-list gets a dev entry. Rebuilding a PyInstaller binary for every Python change would be painful, so debug builds should run the backend straight from its venv:

#[cfg(debug_assertions)]
let cmd = app.shell()
    .command("../../../services/backend/.venv/bin/python")   // .venv\Scripts\python.exe on Windows
    .args(["-m", "app.main", "--dev", "--data-dir", dev_dir])
    .current_dir("../../../services/backend");
#[cfg(not(debug_assertions))]
let cmd = app.shell().sidecar("agenda-backend")?.args(["--data-dir", data_dir]);

Everything else (stdin secret, AGENDA_READY, health polling) stays identical, so dev exercises the real handshake. For backend-only work, run python -m app.main --dev by hand, type any token on stdin, and use curl with -H "Authorization: Bearer <that token>".

11 / Glossary

Terms used above

IPCInter-process communication. In Tauri, the invoke and event bridge between page JavaScript and Rust.
SidecarAn extra executable bundled with the app and launched by it. Here, the frozen Python backend.
externalBinThe tauri.conf.json key listing sidecars. Each file is suffixed with a Rust target triple.
Target tripleRust's platform name, e.g. aarch64-apple-darwin: CPU, vendor, OS (and ABI).
CapabilityA Tauri v2 JSON file granting specific plugin permissions to specific windows.
LoopbackThe 127.0.0.1 interface. Traffic never leaves the machine, but any local process can connect.
OriginScheme + host + port of a page. tauri://localhost and http://127.0.0.1:51873 are different origins.
CORS preflightThe OPTIONS request a browser engine sends before a cross-origin request with custom headers.
CSPContent Security Policy. Page-level rules for where scripts may load from and connect to.
Bearer tokenAuthorization: Bearer <value>. Whoever holds the value is trusted. Here, the per-launch secret.
ASGI / uvicornThe Python async web-server interface, and the server that implements it and runs FastAPI.
OpenAPIA JSON description of every endpoint and schema. FastAPI generates it, and TS types are generated from it.
PKCEProof Key for Code Exchange. It stops an intercepted OAuth code from being used by anyone but the app that started the flow.
WALSQLite write-ahead log mode. Readers don't block the single writer.
